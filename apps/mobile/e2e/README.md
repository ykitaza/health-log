# E2E テスト（Playwright）

Android のエミュレーターや実機を使わずに画面の流れを確かめるため、Expo の web 向けの書き出し（`dist/`）を、
Pixel と同じ 412×915 の画面の Chromium で操作する。計算の関数とリポジトリの層は jest（`lib/__tests__`、`db/__tests__`）で確かめている。

## 動かし方

```sh
cd apps/mobile
npm ci
npm run e2e:build                    # npx expo export --platform web（dist/ に書き出す）
npx playwright install chromium      # 初めてのときだけ
npm run e2e                          # npx playwright test
```

- 画面のコードを変えたら、`npm run e2e:build` で書き出し直す（テストは `dist/` を見る）
- 配信は `e2e/serve.mjs`（依存なしの小さなサーバー）。Playwright の `webServer` が `http://127.0.0.1:8090` で起動する。ポートは `E2E_PORT` で変えられる（8081 は Metro が使う）
- 1つだけ流す：`npx playwright test e2e/body.spec.ts -g "目標体重"`
- 失敗したときは `test-results/` にトレースとスクリーンショットが残る：`npx playwright show-trace test-results/<テスト>/trace.zip`

## expo-sqlite を web で動かすための設定

[Expo の expo-sqlite のドキュメント](https://docs.expo.dev/versions/latest/sdk/sqlite/#web-setup)のとおり。

- `metro.config.js`：SQLite の wasm を読み込めるよう `assetExts` に `wasm` を足す。開発サーバー（`npx expo start --web`）では COEP と COOP のヘッダーを付ける
- `e2e/serve.mjs`：書き出したものを配信するときに、同じヘッダー（`Cross-Origin-Embedder-Policy: credentialless`、`Cross-Origin-Opener-Policy: same-origin`）を付ける。SharedArrayBuffer を使うために要る

Android と iOS の動きは、この設定では変わらない。

## 書き方の決まり

- **日付**：`page.clock.setFixedTime` で、日本時間（`timezoneId: 'Asia/Tokyo'`）の 2026-11-08（日曜）の朝 10 時に固定する。過去の日の記録は、時刻をその日に変えてから画面で記録して作る（`recordOn`）
- **データ**：テストごとに新しいブラウザのコンテキストなので、まっさらな DB から始まる。必要なデータは、テストの中で画面を操作して作る
- **要素の探し方**：役割と名前（`getByRole`）か、表示の文字（`see`）。数字のカードやカレンダーの日など、文字で探しにくいものは `testID`（web では `data-testid`）
- **共通の操作**は `helpers.ts` にまとめる（`openApp`、`recordToday`、`addEntry`、`fillSets`、`enter`、`goTab` など）
- **隠れた画面に注意**：スタックの下の画面やほかのタブも DOM に残っている。ほかのタブは `aria-hidden="true"` で後ろに重なっているだけなので、文字は `see`（見えていて aria-hidden の中にないもの）で探す。画面が切り替わったら、次の画面の見出しなどが出るのを待ってから押す（切り替わりの途中は、前の画面の同じ名前のボタンも見えている）
- **保存を待つ**：体組成と設定は、欄を離れたときに非同期で保存する。再読み込みの前に、計算の値（BMI など）や推移の画面に保存した値が出るのを待つ。決まった時間だけ待つ（`waitForTimeout`）書き方はしない
- やり直し（retries）はしない。不安定なテストを隠さないため

## web では確かめられないこと

このテストは web の Chromium で動かすので、次のことは確かめていない。Pixel の Expo Go などで手で確かめる。

- **数字のキーボード**：`keyboardType="decimal-pad"` などは web では効かない（文字も打てる）。数字でない文字のふるまいは、web で打てる分だけ確かめた
- **キーボードに入力欄が隠れないか**、キーボードを閉じたときに欄を離れる（保存する）こと
- **Android の戻るボタンとジェスチャー**：テストは画面の「戻る」ボタン、ブラウザの戻ると再読み込みだけ。入力の途中で戻るときの確認（expo-router の `usePreventRemove`）が、Android の戻るボタンとジェスチャーでも出ることは実機で確かめる
- **共有の画面**：CSV の書き出しは `Share.share` が OS の共有のメニューを開く。web では `navigator.share` に置き換わるので、テストではそれを差し替えて、渡した中身（CSV）を確かめた。共有のメニューの見た目と、保存先のアプリに渡ることは確かめていない
- **フォントの描画と文字の収まり**：`adjustsFontSizeToFit`（ボタンの文字を縮めて1行に収める）は web では効かず「…」で切れる。Barlow Condensed と Noto Sans JP の Android での見た目
- **SQLite の保存先**：web は OPFS、Android はアプリのファイル。アプリを閉じても残ることは、web の再読み込みでしか確かめていない
- **端末の時刻とタイムゾーン**：日付の切り替わりはブラウザの時刻を固定して確かめた
- **体重計の取り込み（Health Connect）による1日に複数の記録**：画面からは作れないので、選び方は jest（`db/__tests__/repositories.test.ts`、`lib/__tests__/body.test.ts`）で確かめている
