# hlog

筋トレ・体組成・食事を記録するスマホのアプリです。Expo（SDK 58）と expo-router で作り、Pixel（Android）で使う前提です。

記録は先に端末の SQLite に保存します。設定の画面からログイン（任意）すると、筋トレ・種目・部位・体組成・設定・食事をサーバーと同期し、チャット（MCP）で記録したものも届きます。ログインしていないあいだは端末にだけあり、アプリを消すと記録も消えるので、残したいときは設定の画面から CSV で書き出します。

## できること

- 筋トレの記録：種目を選び、重量・回数・メモを入れる。前回の表示とコピー、自己ベスト、種目の並べ替え
- ホーム：今週の合計負荷量、BIG3 の推定1RM の合計、今週の目標、カレンダー（筋トレと食事の記録の日）、今週やること、「記録する」
- 推移：BIG3 の推定1RM の合計、総負荷量（週・日）、自己ベスト、種目ごとの推定1RM の折れ線とその種目の記録（新しい順）
- 体組成：体重・体脂肪率（とメモ）、除脂肪体重・BMI などの計算、推移（7日の平均）、目標体重までのペース
- 設定：kg と lb、セット数の初期値、休憩のタイマー、今週の目標（筋トレ・食事の記録・睡眠）、身長と目標体重、CSV の書き出し
- Health Connect（Android）：体重計などの体重・体脂肪率と、睡眠・心拍（1日のまとめ）・歩数（1日の合計）を取り込む（読み取りだけ。アプリを開いたとき・前面に戻ったとき）。同じ日に手入力があれば手入力を出す
- RM計算機、種目と部位の追加・名前の変更・非表示、BIG3 の割り当てとフォームの動画のリンク、休憩のタイマー、前回のメニューを写す
- ログイン（任意）：設定 → ログイン。Cognito のマネージドログインにパスキーで入り、アプリ用の API に1回つないで確かめる（下の「ログイン」）

画面ごとにできることは次のとおりです。

下のタブは ホーム・筋トレ・食事・からだ・レポート の5つ。どのタブにも右上に設定の歯車がある。

| 画面 | できること |

| ホーム | 合計負荷量／今週（月曜始まりの週の、月曜から今日まで。車の何台分か）、BIG3 推定1RM 合計（筋トレの推移の「BIG3 の推定1RM（合計）」と同じ計算。大きな数字、3か月の小さな折れ線、先月との差。押すと筋トレの推移。3種目がそろうまでは「—」と「BIG3 の記録がまだありません」）、今週の目標（筋トレの回数と食事を記録した日数。数字と細い棒で、目標に届いたら棒を満たす。睡眠の目標は週のレポートで見せる）とカレンダー（筋トレの日は緑の丸の枠、食事を記録した日は右上に白い点。下に凡例）。その日の「トレーニング」（種目数・セット数・合計負荷量。前の夜の睡眠が6時間未満の今日は「今日は軽めでも大丈夫」のひとこと）・「食事」（kcal とたんぱく質の残り、日の種類）・「体調」（体重・睡眠・安静時心拍と、目標体重まで）の小さなカード（押すとそれぞれの画面へ）。今週やること（最新の週のまとめの次の一歩をチェックの一覧で。チェックは端末の中だけ）。右下の「記録する」で下からのシート：筋トレ（その日のトレーニング）・食事（今日は時刻から区分を決めて品目の入力、過去の日はその日の食事のタブ）・体重（からだのタブで計測のシート）・AI で記録（食事の文で ChatGPT か Claude）。カレンダーで今月の過去の日を押すと、その日のカードに変わり「記録する」もその日になる（「今日に戻る」で戻す。未来の日は押せない）。同期でほかから食事・筋トレを受け取ったら「食事を2件、筋トレを1件取り込みました」と「見る」。レポートのお知らせ（カレンダーと負荷量の下に1つだけ）：まだ開いていないレポートがあれば「新しいレポートが ◯ 件」（「見る」で1件ならそのレポート、2件以上なら一覧を新しい順で。「×」で今出ている分を見たことにする。見たかどうかは端末だけに覚え、この機能が入って初めて動いたときは、今あるレポートを全部見たことにする）。なければ、まだ作っていないまとめのおすすめ（「まとめがまだ ◯ 件あります」。「作る」でまとめて頼む文を入れて ChatGPT か Claude を開き、「×」で今出ている分を閉じる）。最新のレポート（なければ、チャットで頼む方法）。ホームのレポートの入口（「すべて」、お知らせの「見る」で2件以上）はレポートのタブへ移る |
| 筋トレ（タブ） | 上の切り替えで「記録」（下のトレーニング）と「推移」（下の筋トレの推移）。記録は、上の日付の切り替え（前の日・次の日、左右のスワイプ（下の「左右のスワイプ」）。未来へは進めない）で選んだ日のトレーニング。日付を押すと「日を選ぶ」の下からのシート（月のカレンダー、筋トレをした日に点、今日より後は押せない。日を押すと閉じてその日になる）。今日以外の日は日付の下に「今日ではない日を見ています」と「今日に戻る」（Android の戻るでもまず今日に戻る）。ホームのカードなどが開く前のその日の画面の道（`/workout?date=`）は、このタブのその日へ移る。右上に RM計算機の入口 |
| トレーニング（筋トレのタブの記録） | その日の種目の一覧（上のまとめに種目数・部位（「胸・肩」。3つ以上は先頭の2つと「ほか ◯」）・セット数・合計負荷量。見出しは「記録した種目」）。その日の日のまとめの筋トレの分は「レポートから（今日のまとめ）」（過去の日は「レポートから（11月6日のまとめ）」）として、塗りのない点線の枠と書類のアイコンのカードで出し、記録のカードと分ける（食事・からだのタブも同じ）。種目の追加、↑↓ での並べ替え、種目を押して記録を直す・消す。過去の日なら、その日に記録していることを上に出す（種目の選択・記録の入力も同じ。前回・自己ベスト・何種目目はその日を基準にする）。種目のカードは1行目に順番と名前、2行目に部位の札（種目と部位の管理で決めた名前）・BIG3 の印（割り当てた種目）・推定1RM。今日が空なら「前回のメニュー」（直近のトレーニングの日の日付・部位・種目）と「同じメニューで始める」（重さと回数を未完了のセットとして写す。メモと完了は写さない）。休憩のタイマーが動いていれば下に帯 |
| 種目を選ぶ | 検索、部位で絞る、部位ごとの一覧、種目ごとの前回の記録。種目の追加 |
| 記録の入力 | セットごとの重量・回数・完了。前回の記録の表示とコピー、上のセットのコピー、セットの追加、元に戻す。今日のセットを完了にすると休憩のタイマー（設定の秒数。帯に残り時間、「+30秒」「止める」。0 で振動して消える。画面をまたいで1つ。アプリが裏にあるあいだは数えず、前面に戻ったときに過ぎていれば消すだけ）。BIG3 の印、フォームの動画のリンクがある種目は右上の「フォーム」で外のアプリを開く |
| 筋トレの推移 | 種目のチップ1列（すべて・記録のある種目）とグラフ。すべてなら BIG3 の推定1RM の合計（3か月の折れ線、先月との差、3種目それぞれ。そろわないあいだは何を割り当てる・記録すると出るか）、総負荷量（週・日。週は月曜始まり）、種目ごとの自己ベスト（押すとその種目）。種目を選ぶと、その種目の推定1RM（いちばん新しい日の値と先月との差、3か月の折れ線。回数だけの種目は総負荷量）と、その種目の記録（新しい順に10日ずつ、「もっと見る」で読み足す。日付と部位の札・セット・総負荷量・推定1RM。押すと記録のタブのその日） |
| からだ（タブ） | 上の切り替えで「今日」と「推移」。今日は日ごとの計測を見る画面：体重（Health Connect から取り込んだ値なら「取り込み」の印。手入力があれば手入力を出す）、週の平均（月曜始まりの週の、記録のある日の平均）と目標体重まで（目標を設定したとき）、体脂肪率・除脂肪体重・BMI（身長を設定したとき）のタイル（押すと項目の推移）、メモ。記録がない日は前回の体重。「入力・編集」「計測を入れる」で下からのシートを開き、体重・体脂肪率・メモを入れて保存する（欄の下に取り込みの値。欄を空にして保存すると手入力の値だけを消し、取り込みの値に戻る）。取り込んだ睡眠（その日に起きた分の合計と時刻）と心拍（安静時・平均・最低〜最高）と歩数（1日の合計。歩数の許可がないあいだは「新しいアプリで許可すると取り込めます」）。推移は、1か月の体重の推移（7日の平均の線、目標体重）、目標体重までの残りとペース、睡眠（直近7日の棒、7時間以上の日）、安静時心拍（直近7日）、歩数（直近7日の棒、7日の平均、いちばん多い日）。カードを押すと詳しい推移へ |
| 体組成の推移 | 項目（体重・体脂肪率・BMI・体脂肪量・除脂肪体重）ごとの推移のグラフと記録の一覧。体重は7日の平均の線と、目標体重までの残り |
| レポート（タブ・中身） | Claude・ChatGPT が MCP の save_report で書いたまとめ。一覧は下のタブの5つ目（前の一覧の道 `/reports` もこのタブで開く）。いちばん上にホームと同じ新しいレポートのお知らせとまだのまとめのおすすめ（2つとも出し、新着を上に。見たこと・閉じたことはホームと同じ所に覚えるので、片方で閉じるともう片方にも出ない）、右下の「レポートを作る」（ホームの「チャットで作る」と同じシート。閉じていないまだのまとめがあれば、それをまとめて頼む文で開く）。中身は一覧の上に開き、戻るで一覧へ（URL で直接開いて戻る先がなければ、レポートのタブへ）。一覧は期間の日付（期間の最後の日。なければ初日、それもなければ作った日）の新しい順で、月の見出しも同じ日付で分ける。同じ日付なら期間の長いもの（月→週→日）、その次に作った日の新しいものが先。種類のチップの右の「新しい順／古い順」で入れ替え（端末だけに覚える）。カードは上の行の左に種類の四角（「日」「週」「月」「他」の1文字。読み上げは「週のまとめ」など）、調子（良い調子・いつもどおり・気をつけたい）をアイコンと言葉で出し（色の帯は使わない）、日付は並びと同じ日付、主な指標を2つまで。高さをそろえるため、題と要約は1行ずつ（長ければ「…」）、指標は1段に入る分だけ、指標や要約がなくても同じ高さ（高さは行の数で決まるので、文字の大きさの設定に合わせて伸びる）。まだ開いていないものに「新着」の札。右上の「自動で作る」（設定の「チャットとの連携」にも入口）で、ChatGPT のスケジュール（タスク）に日（毎日 22:00、その日の分）・週（毎週月曜 8:00、先週の分）・月（毎月1日 8:00、先月の分）のまとめを作る予定を入れてもらう文で ChatGPT を開く（すでに hlog のまとめの予定があれば作らずに教えてもらう。各回は list_reports で同じ種類・期間のまとめがあれば作らず、なければ period_overview を読んで save_report で保存。頼んだ日を端末に覚えて出す。Claude のスケジュールは、いまは自作のコネクタを使えないため ChatGPT だけ）。中身は種類ごとに並びを変える。日は「今日の達成」（筋トレ・kcal・たんぱく質・睡眠を目標に対する棒と印で）、週は「今週の目標」（筋トレ・食事を記録した日・たんぱく質が目標に届いた日・7時間以上寝た日）、月は「体の変化」（体重の7日の平均の推移と目標、目標までの残りとペース）を、アプリが自分の記録から出す（レポートに保存された数字ではない。`lib/reports.ts`）。そのあとに指標のタイル（前の期間からの変化。日は出さない）、つながり（分野をまたぐ気づき）、分野ごとのカード、目標の見直し（食事の目標なら「食事の目標を開く」）、次の一歩、本文（Markdown の見出し・箇条書き・太字・段落だけを整え、ほかは文字のまま）。前の形のレポートは、ある分だけ出す。読むのと消す（確認つき）だけ。ホームの「最新のレポート」から開く。「チャットで作る」の頼みの文（`lib/chat.ts`）は、MCP の period_overview でその期間を読み、種類ごとに書くもの（日は明日の一歩を1つ、週はつながりと来週の一歩、月は体重のペース・つながり・目標の見直し）を頼む |
| RM計算機 | 重量と回数から推定1RM（重量 ×（1 ＋ 回数 ÷ 30））と、割合ごとの重量・回数の目安（入口は筋トレのタブの右上） |
| 種目と部位の管理 | 種目と部位の追加、名前の変更（種目は部位も、種目を押して編集の画面で）。種目の BIG3 の役（なし・ベンチプレス・スクワット・デッドリフト。1つの役は1つの種目で、付け替えると前の種目から外す。割り当てる前は名前で決める。3つそろうと月のレポートに BIG3（合計）のタイルも出る）とフォームの動画のリンク（https:// だけ）。使わなくなった種目・部位は消さずに非表示にする（記録は残る。部位の非表示はアプリだけでできる） |
| 設定 | 記録の初期値（重さの単位 kg・lb、セット数の初期値、休憩のタイマー：切・60・90・120・180秒）、今週の目標（筋トレの回数 2〜6、食事を記録する日数 3・5・7、7時間以上寝る日数 切・3・4・5・7。週は月〜日）、身長と目標体重、種目と部位の管理と食事の目標への入口、筋トレの記録の CSV の書き出し、ログインと Health Connect への入口。休憩のタイマーと今週の目標も、ほかの設定と同じく同期する（同期の ID は `rest_timer_seconds`・`weekly_goal_training_days`・`weekly_goal_meal_days`・`weekly_goal_sleep_days`） |
| Health Connect | 連携する・切る、最後に取り込んだ時刻、今すぐ取り込む、歩数の許可がないときは「歩数を許可する」、読むもの・送る先・見られる人の説明（Health Connect の権限の画面の「プライバシー ポリシー」からも開く） |
| アカウント（ログイン） | パスキーでのログイン（任意）、アプリ用の API とのつながりの確認、ログアウト |
| 食事（タブ） | 上の切り替えで「記録」と「推移」（週のまとめ）。記録は、上の日付の切り替え（前の日・次の日、左右のスワイプ（下の「左右のスワイプ」）。日付を押すと筋トレと同じ「日を選ぶ」のシートで、食事を記録した日に点）で選んだ日（過去の日も）の区分（朝食・昼食・夕食・間食）ごとの食事、合計（kcal・PFC）と目標の残り、日の種類（筋トレの日／休みの日。バッジを押すと切り替え）。記録：品目を手で入れる・kcal と PFC だけ・いつもの・昨日と同じ。食事の詳細で量の変更（栄養も同じ割合）、品目の追加・削除、日付と区分の変更、削除（確認つき）、いつものとして保存。MCP で記録した食事は、推定の根拠（AI が kcal と PFC を推定した理由）も出す。AI の推定はしない（写真からの推定は Claude・ChatGPT で行う） |

| 食事の推移（週のまとめ） | 前の週・次の週（ボタンと左右のスワイプ。下の「左右のスワイプ」）。7日の kcal と目標、PFC の割合、週の平均（記録した日だけ）と目標との差 |

### 左右のスワイプ（食事の記録・推移、筋トレの記録）

- 日付の切り替えは動かさず、その下の中身が指についてくる。放して日（週）が変わるときは、今の中身が指の向きへ出ていき、次の中身が反対の側からすべって入る（合わせて 250ms。出ていく半分は ease-in、入る半分は ease-out、はね返りなし）。足りなければ 250ms の ease-out で元の位置へ戻る
- ＜ ＞ のボタン、「日を選ぶ」のシート（前の日か後の日かで向きを決める）、「今日に戻る」・Android の戻るで日が変わるときも、同じ横すべり
- 今日（今週）より先へ引くと、指の動きより小さく（ゴムのように抵抗して、72dp まで）動き、放すと戻る。日は変わらない
- 最初の数回だけ、開いたときに中身が 24dp ずれて戻り（今日・今週で次へ進めないときは右＝前の向き、過去の日なら左＝次の向き）、日付の切り替えの下に「左右にスワイプで日を移れます」（推移は「週」）を出す。読み上げにも出す。一度スワイプで日（週）を動かしたら、どの画面でももう出さない。スワイプしなくても、1つの画面で3回まで。端末だけに覚える（同期しない `sync_meta` の `swipe_hint.*`）
- 動きを減らす設定なら、指についてこず、すべらず、ヒントもずらさない（結果と文だけ）
- 指を受け取る判定（横に 24dp、縦の倍以上）は前と同じなので、縦のスクロールと押す操作はそのまま。計算は `lib/swipe.ts`、動きは `components/DayPicker.tsx` の `SwipeArea`・`usePageSlide`

## 動かし方

Node の版は `.node-version` で決めています。[fnm](https://github.com/Schniz/fnm) で合わせます。

```sh
cd apps/mobile
fnm install && fnm use   # .node-version の版を入れて使う
npm ci
npx expo start
```

スマホに Expo Go を入れ、画面に出た QR コードを読み取ると開きます。PC とスマホは同じ Wi-Fi につないでおきます。

- **同じ Wi-Fi でもつながらないとき**：ルーターが端末どうしの通信を止めている（ゲスト用の Wi-Fi など）か、PC のファイアウォールが Metro のポート（8081）を止めていることがあります。`npx expo start --tunnel` なら、インターネット経由でつなげます（初めてのときは `@expo/ngrok` を入れるか聞かれます）
- **ログインは Expo Go ではできません**（戻り先の `torelog://callback` を Expo Go が受け取れないため）。開発ビルド（`eas build --profile development`）か、配った APK で使います
- ブラウザで見るときは `npx expo start --web` です。web でも expo-sqlite が動くよう、`metro.config.js` に設定を足しています（[E2E テスト](e2e/README.md#expo-sqlite-を-web-で動かすための設定)）

## ログイン

Cognito のマネージドログイン（MCP と同じユーザーのパスキー）に、認可コード＋PKCE でつなぎます。設計は [docs/design.md](../../docs/design.md#スマホアプリhlogのログイン) にあります。

1. 設定 → ログイン →「パスキーでログイン」で、Chrome Custom Tabs にログインの画面が開く（毎回 `prompt=login`）
2. パスキーで入ると `torelog://callback` に戻り、認可コードをトークンに換える（`lib/auth/session.ts`。シークレットは使わない）
3. 換えたあと（うまくいかなくても）、同じブラウザで Cognito の `/logout` を開いてセッションの Cookie を消し、`torelog://signout` で自動で閉じる。Cookie が残る1時間のあいだ、`torelog://` を登録した別のアプリが画面なしでコードを受け取れてしまうため
4. ログインしたら同期を始める（下の「同期」）

- トークンは expo-secure-store（Android の Keystore で暗号化。自動バックアップから外す）にだけ置く。ID トークンは求めない（scope は `torelog-api/` の4つだけ）。web は安全な保存先がないので、メモリーにだけ置く
- アクセストークンは15分。切れる1分前から、リフレッシュトークン（30日、使うたびに新しくなる）で更新する。リフレッシュトークンが切れていたら、ログインしていない状態に戻して知らせる
- ログアウト：端末のトークンを消してから、Cognito の `/oauth2/revoke` でリフレッシュトークンを取り消す
- 値（クライアント ID、Cognito のドメイン、API の URL）は `app.json` の `extra.torelog`。どれも秘密ではない（`cdk deploy` の出力 `AppClientId`・`CognitoDomain`・`AppApiUrl`）。変えたあと web で確かめるときは `npx expo export --platform web --clear`（Metro の変換のキャッシュに古い値が残る）
- 画面の道：`app/account.tsx`（ログイン）、`app/callback.tsx`（web の戻り先）、`app/+native-intent.tsx`（`torelog://callback`・`torelog://signout` で画面を動かさない）。状態は `hooks/auth.tsx` がアプリ全体で持ち、同期もこれを使う

## 同期

設計は [docs/sync-design.md](../../docs/sync-design.md#アプリの同期appsmobile) にあります。

- 記録・編集・削除のたびに、表のトリガーが `sync_outbox` に変更を積む（`db/syncSpec.ts`、`db/migrations.ts` の版2）。ログインの前の記録も、版2のマイグレーションで積む
- ログインしているときだけ、起動・前面に戻ったとき・保存のあと（3秒まとめる）・アカウントの画面の「今すぐ同期」で、送る → 受け取る → 当てはめる（`lib/sync/engine.ts`、`lib/sync/scheduler.ts`、`hooks/sync.tsx`）
- 端末は衝突の決まりを持たず、サーバーが返した状態で上書きする。まだ送っていない項目は端末の値を残す（`db/repositories/sync.ts`）
- 受け取った変更のうち、ほかから新しく作られた食事（1件ずつ）と筋トレ（日ごと）を数え、ホームに知らせる（`lib/sync/received.ts`。自分の端末から送った分と、初めての同期のスナップショットは数えない）
- 通信の失敗は、間を倍にしながらやり直す。サーバーに断られた変更は印を付けて飛ばし、アカウントの画面に件数を出す
- Health Connect の取り込みは、`sync_meta` に `importing` を置いて書き、トリガーが `origin = import` で積む（版4。サーバーで手入力より弱く当てはめる）。差分のトークンも `sync_meta` に持つ（[docs/sync-design.md](../../docs/sync-design.md#health-connect-の取り込み)）
- 食事（食事・品目・いつもの・目標・日の種類）も同じ仕組みで同期する（版3）。品目は食事の中でだけ一意なので、`(meal_id, id)` で指し、変更に `parent_id` を付ける。版2までの端末は食事の状態を捨てていたので、版3で受け取りの位置を消して、スナップショットを1回取り直す
- レポートのつながり（links）と目標の見直し（review）は版9で列を足した。版8までの端末は受け取ったレポートのこの2つを捨てていたので、版9で受け取りの位置とレポートの当てはめた印（`sync_seen`）を消し、スナップショットを1回取り直して、受け取り済みのレポートにも当てはめ直す（同じ ID の行を上書きするので重ならない）

## テスト

```sh
npx tsc --noEmit   # 型チェック
npx expo lint      # ESLint（eslint-config-expo。設定は eslint.config.js）
npx jest           # 計算の関数（lib/__tests__）と、DB のリポジトリ（db/__tests__）
npx expo-doctor    # Expo の設定と依存の版を確かめる
```

jest の DB のテストは、expo-sqlite の代わりに Node の `node:sqlite`（メモリー上）を使います（`test-utils/nodeDb.ts`）。同期のテストは、偽の同期サーバー（`test-utils/fakeSyncServer.ts`）に当て、本物の API には当てません。サーバーと同じテストのデータ（`testdata/sync/`）も使います。

画面の E2E テストは、Expo の web 向けの書き出しを Playwright で操作します。動かし方と書き方の決まりは [e2e/README.md](e2e/README.md) にあります。

CI（`.github/workflows/test.yml`）では、型チェック・lint・jest・E2E を動かします。

## Pixel への配信

EAS Build で APK を作って Pixel に入れ、JS の変更は EAS Update で配信します（Play ストアには出しません）。設定の中身と、Expo のアカウントの作り方からの手順は [docs/eas.md](docs/eas.md) にあります。

- `.github/workflows/eas-update.yml`：main の test が通ったあと、`apps/mobile/` が変わっていれば `preview` のチャンネルに配信する
- `.github/workflows/eas-build.yml`：手動で APK を作る（ネイティブを変えたとき）

## フォルダの構成

| フォルダ | 中身 |
|---|---|
| `app/` | 画面。expo-router がファイルの名前で道を決める（`(tabs)/` は下のタブ、`workout/` は筋トレの記録、`exercises/` は種目の管理、`reports/` はレポート） |
| `components/` | 画面で使う部品（文字、カード、アイコン、カレンダー、グラフ） |
| `hooks/` | 画面から DB を読む処理（`data.ts`。週・日の達成と、まだ作っていないまとめも）、入力の途中で戻るときの確認（`confirmDiscard.tsx`）、ログインの状態（`auth.tsx`）、同期（`sync.tsx`）、Health Connect の連携（`healthConnect.tsx`） |
| `db/` | SQLite。表の定義（`migrations.ts`）、初期の部位と種目（`seed.ts`）、読み書き（`repositories/`）、同期する種類と outbox のトリガー（`syncSpec.ts`）。書き込みは1つずつ順に行う（`serial.ts`） |
| `lib/` | 計算と変換（負荷量、推定1RM、体組成と移動平均、週・日の達成（`goals.ts`）、まだ作っていないまとめ（`reports.ts`）、単位、日付、入力の範囲、CSV）、ログインのトークンの扱い（`auth/`）、アプリ用の API のクライアント（`api.ts`）、同期の流れといつ動かすか（`sync/`）、Health Connect の取り込み（`healthConnect/`） |
| `plugins/` | 自分の config plugin（Health Connect の権限の説明の intent を `torelog://health-privacy` に変える） |
| `theme/` | 色と文字 |
| `e2e/` | 画面の E2E テスト（Playwright） |
| `docs/` | Pixel への配信（EAS）の手順 |
| `test-utils/` | jest で使う、メモリー上の DB と偽の同期サーバー（E2E も使う）、偽の Health Connect |
| `assets/` | アイコンとスプラッシュの画像 |

どの表も、サーバーと同期するために、ID（UUID）、作成・更新の時刻、論理削除の列を持ちます（`db/migrations.ts`）。

## 依存の更新

- Expo の SDK が版を決めるもの（`node_modules/expo/bundledNativeModules.json` に載っているもの。`expo-*`、`react`、`react-native`、`react-native-*` など）は、`npm install` で版を指定せず、`npx expo install <名前>` で入れます。SDK を上げるときは `npx expo install --fix` で揃えます
- Dependabot（`.github/dependabot.yml`）も同じ考え方で、これらの版の更新の PR を作りません。依存を足すときは、`bundledNativeModules.json` に載っていれば、Dependabot の ignore にも足します
- それ以外（jest、Playwright など）は、Dependabot の PR で上げます
- 上げたあとは `npx expo-doctor` で、版が SDK と合っているかを確かめます
