# hlog

筋トレ・体組成・食事を記録するスマホのアプリです。Expo（SDK 58）と expo-router で作り、Pixel（Android）で使う前提です。

記録は先に端末の SQLite に保存します。設定の画面からログイン（任意）すると、筋トレ・種目・部位・体組成・設定・食事をサーバーと同期し、チャット（MCP）で記録したものも届きます。ログインしていないあいだは端末にだけあり、アプリを消すと記録も消えるので、残したいときは設定の画面から CSV で書き出します。

## できること

- 筋トレの記録：種目を選び、重量・回数・メモを入れる。前回の表示とコピー、自己ベスト、種目の並べ替え
- ホーム：総負荷量（7日・28日・総合計）、週ごとの棒、カレンダー、推定1RM
- 履歴と分析：カレンダー、種目ごとのグラフ、自己ベスト
- 体組成：体重・体脂肪率（とメモ）、除脂肪体重・BMI などの計算、推移（7日の平均）、目標体重までのペース
- 設定：kg と lb、セット数の初期値、身長と目標体重、CSV の書き出し
- Health Connect（Android）：体重計などの体重・体脂肪率と、睡眠・心拍（1日のまとめ）を取り込む（読み取りだけ。アプリを開いたとき・前面に戻ったとき）。同じ日に手入力があれば手入力を出す
- RM計算機、種目と部位の追加・名前の変更・非表示
- ログイン（任意）：設定 → ログイン。Cognito のマネージドログインにパスキーで入り、アプリ用の API に1回つないで確かめる（下の「ログイン」）

画面ごとにできることは次のとおりです。

下のタブは ホーム・筋トレ・食事・からだ の4つ。どのタブにも右上に設定の歯車がある。

| 画面 | できること |
|---|---|
| ホーム | 合計負荷量（7日間・28日間・総合計）とカレンダー。その日の「トレーニング」（種目数・セット数・合計負荷量）・「食事」（kcal とたんぱく質の残り、日の種類）・「体調」（体重・睡眠・安静時心拍）の小さなカード（押すとそれぞれの画面へ）。「今日のトレーニングを追加」（右下）と RM計算機への入口。カレンダーで今月の過去の日を押すと、その日のカードに変わり「〇月〇日のトレーニングを追加」で足せる（「今日に戻る」で戻す。未来の日は押せない）。最新のレポート（なければ、チャットで頼む方法） |
| 筋トレ（タブ） | 上の切り替えで「今日」（今日のトレーニングと同じ中身）と「履歴」（下の筋トレの履歴） |
| トレーニング（その日の記録） | その日の種目の一覧（種目数・セット数・合計負荷量）。種目の追加、↑↓ での並べ替え、種目を押して記録を直す・消す。過去の日なら、その日に記録していることを上に出す（種目の選択・記録の入力も同じ。前回・自己ベスト・何種目目はその日を基準にする） |
| 種目を選ぶ | 検索、部位で絞る、部位ごとの一覧、種目ごとの前回の記録。種目の追加 |
| 記録の入力 | セットごとの重量・回数・完了。前回の記録の表示とコピー、上のセットのコピー、セットの追加、元に戻す |
| 筋トレの履歴 | 月のカレンダー（部位・種目で絞る。選んだ日に種目を足せる）、種目ごとの総負荷量と推定1RM のグラフ、週ごとの総負荷量、種目ごとの自己ベスト（推定1RM） |
| からだ（タブ） | 上の切り替えで「今日」と「推移」。今日は日ごとの計測を見る画面：体重（Health Connect から取り込んだ値なら「取り込み」の印。手入力があれば手入力を出す）、週の平均（月曜始まりの週の、記録のある日の平均）と目標体重まで（目標を設定したとき）、体脂肪率・除脂肪体重・BMI（身長を設定したとき）のタイル（押すと項目の推移）、メモ。記録がない日は前回の体重。「入力・編集」「計測を入れる」で下からのシートを開き、体重・体脂肪率・メモを入れて保存する（欄の下に取り込みの値。欄を空にして保存すると手入力の値だけを消し、取り込みの値に戻る）。取り込んだ睡眠（その日に起きた分の合計と時刻）と心拍（安静時・平均・最低〜最高）。推移は、1か月の体重の推移（7日の平均の線、目標体重）、目標体重までの残りとペース、睡眠（直近7日の棒、7時間以上の日）、安静時心拍（直近7日）。カードを押すと詳しい推移へ |
| 体組成の推移 | 項目（体重・体脂肪率・BMI・体脂肪量・除脂肪体重）ごとの推移のグラフと記録の一覧。体重は7日の平均の線と、目標体重までの残り |
| レポート（一覧・中身） | Claude・ChatGPT が MCP の save_report で書いたまとめ。一覧は新しい順で、調子（良い調子・いつもどおり・気をつけたい）を色・アイコン・言葉で出し、主な指標を2つまで。中身は調子の帯、指標のタイル（前の期間からの変化）、分野ごとのカード、次の一歩、本文（Markdown の見出し・箇条書き・太字・段落だけを整え、ほかは文字のまま）。読むのと消す（確認つき）だけ。ホームの「最新のレポート」から開く |
| RM計算機 | 重量と回数から推定1RM（重量 ×（1 ＋ 回数 ÷ 30））と、割合ごとの重量・回数の目安 |
| 種目と部位の管理 | 種目と部位の追加、名前の変更（種目は部位も、種目を押して編集の画面で）。使わなくなった種目・部位は消さずに非表示にする（記録は残る。部位の非表示はアプリだけでできる） |
| 設定 | 重さの単位（kg・lb）、セット数の初期値、身長と目標体重、筋トレの記録の CSV の書き出し、ログインと Health Connect への入口 |
| Health Connect | 連携する・切る、最後に取り込んだ時刻、今すぐ取り込む、読むもの・送る先・見られる人の説明（Health Connect の権限の画面の「プライバシー ポリシー」からも開く） |
| アカウント（ログイン） | パスキーでのログイン（任意）、アプリ用の API とのつながりの確認、ログアウト |
| 食事（タブ） | 上の切り替えで「記録」と「推移」（週のまとめ）。記録は、日付ごと（過去の日も）の区分（朝食・昼食・夕食・間食）ごとの食事、合計（kcal・PFC）と目標の残り、日の種類（筋トレの日／休みの日。バッジを押すと切り替え）。記録：品目を手で入れる・kcal と PFC だけ・いつもの・昨日と同じ。食事の詳細で量の変更（栄養も同じ割合）、品目の追加・削除、日付と区分の変更、削除（確認つき）、いつものとして保存。MCP で記録した食事は、推定の根拠（AI が kcal と PFC を推定した理由）も出す。AI の推定はしない（写真からの推定は Claude・ChatGPT で行う） |
| 食事の目標 | 今の目標（筋トレの日と休みの日）の確認と、数字での設定（MCP の set_goals と同じ）。「自動で計算」で、体重・体脂肪率の記録と設定から目標を入れる（lib/autoGoal.ts。保存する前に直せる）。設定と食事タブから開く |
| 食事の推移（週のまとめ） | 7日の kcal と目標、PFC の割合、週の平均（記録した日だけ）と目標との差 |

## 動かし方

Node の版は `.node-version` で決めています。[fnm](https://github.com/Schniz/fnm) で合わせます。

```sh
cd apps/mobile
fnm install && fnm use   # .node-version の版を入れて使う
npm ci
npx expo start
```

スマホに Expo Go を入れ、画面に出た QR コードを読み取ると開きます。PC とスマホは同じ Wi-Fi につないでおきます。

- **同じ Wi-Fi でもつながらないとき**：ルーターが端末どうしの通信を止めている（ゲスト用の Wi-Fi など）か、PC のファイアウォールが Metro のポート（8081）を止めていることがあります。`npx expo start --tunnel` なら、インターネット経由でつなげます（初めてのときは `@expo/ngrok` を入れるか聞かれます）
- **ログインは Expo Go ではできません**（戻り先の `torelog://callback` を Expo Go が受け取れないため）。開発ビルド（`eas build --profile development`）か、配った APK で使います
- ブラウザで見るときは `npx expo start --web` です。web でも expo-sqlite が動くよう、`metro.config.js` に設定を足しています（[E2E テスト](e2e/README.md#expo-sqlite-を-web-で動かすための設定)）

## ログイン

Cognito のマネージドログイン（MCP と同じユーザーのパスキー）に、認可コード＋PKCE でつなぎます。設計は [docs/design.md](../../docs/design.md#スマホアプリhlogのログイン) にあります。

1. 設定 → ログイン →「パスキーでログイン」で、Chrome Custom Tabs にログインの画面が開く（毎回 `prompt=login`）
2. パスキーで入ると `torelog://callback` に戻り、認可コードをトークンに換える（`lib/auth/session.ts`。シークレットは使わない）
3. 換えたあと（うまくいかなくても）、同じブラウザで Cognito の `/logout` を開いてセッションの Cookie を消し、`torelog://signout` で自動で閉じる。Cookie が残る1時間のあいだ、`torelog://` を登録した別のアプリが画面なしでコードを受け取れてしまうため
4. ログインしたら同期を始める（下の「同期」）

- トークンは expo-secure-store（Android の Keystore で暗号化。自動バックアップから外す）にだけ置く。ID トークンは求めない（scope は `torelog-api/` の4つだけ）。web は安全な保存先がないので、メモリーにだけ置く
- アクセストークンは15分。切れる1分前から、リフレッシュトークン（30日、使うたびに新しくなる）で更新する。リフレッシュトークンが切れていたら、ログインしていない状態に戻して知らせる
- ログアウト：端末のトークンを消してから、Cognito の `/oauth2/revoke` でリフレッシュトークンを取り消す
- 値（クライアント ID、Cognito のドメイン、API の URL）は `app.json` の `extra.torelog`。どれも秘密ではない（`cdk deploy` の出力 `AppClientId`・`CognitoDomain`・`AppApiUrl`）。変えたあと web で確かめるときは `npx expo export --platform web --clear`（Metro の変換のキャッシュに古い値が残る）
- 画面の道：`app/account.tsx`（ログイン）、`app/callback.tsx`（web の戻り先）、`app/+native-intent.tsx`（`torelog://callback`・`torelog://signout` で画面を動かさない）。状態は `hooks/auth.tsx` がアプリ全体で持ち、同期もこれを使う

## 同期

設計は [docs/sync-design.md](../../docs/sync-design.md#アプリの同期appsmobile) にあります。

- 記録・編集・削除のたびに、表のトリガーが `sync_outbox` に変更を積む（`db/syncSpec.ts`、`db/migrations.ts` の版2）。ログインの前の記録も、版2のマイグレーションで積む
- ログインしているときだけ、起動・前面に戻ったとき・保存のあと（3秒まとめる）・アカウントの画面の「今すぐ同期」で、送る → 受け取る → 当てはめる（`lib/sync/engine.ts`、`lib/sync/scheduler.ts`、`hooks/sync.tsx`）
- 端末は衝突の決まりを持たず、サーバーが返した状態で上書きする。まだ送っていない項目は端末の値を残す（`db/repositories/sync.ts`）
- 通信の失敗は、間を倍にしながらやり直す。サーバーに断られた変更は印を付けて飛ばし、アカウントの画面に件数を出す
- Health Connect の取り込みは、`sync_meta` に `importing` を置いて書き、トリガーが `origin = import` で積む（版4。サーバーで手入力より弱く当てはめる）。差分のトークンも `sync_meta` に持つ（[docs/sync-design.md](../../docs/sync-design.md#health-connect-の取り込み)）
- 食事（食事・品目・いつもの・目標・日の種類）も同じ仕組みで同期する（版3）。品目は食事の中でだけ一意なので、`(meal_id, id)` で指し、変更に `parent_id` を付ける。版2までの端末は食事の状態を捨てていたので、版3で受け取りの位置を消して、スナップショットを1回取り直す

## テスト

```sh
npx tsc --noEmit   # 型チェック
npx expo lint      # ESLint（eslint-config-expo。設定は eslint.config.js）
npx jest           # 計算の関数（lib/__tests__）と、DB のリポジトリ（db/__tests__）
npx expo-doctor    # Expo の設定と依存の版を確かめる
```

jest の DB のテストは、expo-sqlite の代わりに Node の `node:sqlite`（メモリー上）を使います（`test-utils/nodeDb.ts`）。同期のテストは、偽の同期サーバー（`test-utils/fakeSyncServer.ts`）に当て、本物の API には当てません。サーバーと同じテストのデータ（`testdata/sync/`）も使います。

画面の E2E テストは、Expo の web 向けの書き出しを Playwright で操作します。動かし方と書き方の決まりは [e2e/README.md](e2e/README.md) にあります。

CI（`.github/workflows/test.yml`）では、型チェック・lint・jest・E2E を動かします。

## Pixel への配信

EAS Build で APK を作って Pixel に入れ、JS の変更は EAS Update で配信します（Play ストアには出しません）。設定の中身と、Expo のアカウントの作り方からの手順は [docs/eas.md](docs/eas.md) にあります。

- `.github/workflows/eas-update.yml`：main の test が通ったあと、`apps/mobile/` が変わっていれば `preview` のチャンネルに配信する
- `.github/workflows/eas-build.yml`：手動で APK を作る（ネイティブを変えたとき）

## フォルダの構成

| フォルダ | 中身 |
|---|---|
| `app/` | 画面。expo-router がファイルの名前で道を決める（`(tabs)/` は下のタブ、`workout/` は筋トレの記録、`exercises/` は種目の管理、`reports/` はレポート） |
| `components/` | 画面で使う部品（文字、カード、アイコン、カレンダー、グラフ） |
| `hooks/` | 画面から DB を読む処理（`data.ts`）、入力の途中で戻るときの確認（`confirmDiscard.tsx`）、ログインの状態（`auth.tsx`）、同期（`sync.tsx`）、Health Connect の連携（`healthConnect.tsx`） |
| `db/` | SQLite。表の定義（`migrations.ts`）、初期の部位と種目（`seed.ts`）、読み書き（`repositories/`）、同期する種類と outbox のトリガー（`syncSpec.ts`）。書き込みは1つずつ順に行う（`serial.ts`） |
| `lib/` | 計算と変換（負荷量、推定1RM、体組成、単位、日付、入力の範囲、CSV）、ログインのトークンの扱い（`auth/`）、アプリ用の API のクライアント（`api.ts`）、同期の流れといつ動かすか（`sync/`）、Health Connect の取り込み（`healthConnect/`） |
| `plugins/` | 自分の config plugin（Health Connect の権限の説明の intent を `torelog://health-privacy` に変える） |
| `theme/` | 色と文字 |
| `e2e/` | 画面の E2E テスト（Playwright） |
| `docs/` | Pixel への配信（EAS）の手順 |
| `test-utils/` | jest で使う、メモリー上の DB と偽の同期サーバー（E2E も使う）、偽の Health Connect |
| `assets/` | アイコンとスプラッシュの画像 |

どの表も、サーバーと同期するために、ID（UUID）、作成・更新の時刻、論理削除の列を持ちます（`db/migrations.ts`）。

## 依存の更新

- Expo の SDK が版を決めるもの（`node_modules/expo/bundledNativeModules.json` に載っているもの。`expo-*`、`react`、`react-native`、`react-native-*` など）は、`npm install` で版を指定せず、`npx expo install <名前>` で入れます。SDK を上げるときは `npx expo install --fix` で揃えます
- Dependabot（`.github/dependabot.yml`）も同じ考え方で、これらの版の更新の PR を作りません。依存を足すときは、`bundledNativeModules.json` に載っていれば、Dependabot の ignore にも足します
- それ以外（jest、Playwright など）は、Dependabot の PR で上げます
- 上げたあとは `npx expo-doctor` で、版が SDK と合っているかを確かめます
