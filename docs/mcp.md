# Claude・ChatGPT（MCP）で使う

MCP に対応したチャットに、カスタムコネクタとして登録して使います。写真の解析や栄養の推定は Claude・ChatGPT の AI が行い、サーバーは記録と、決まった式での計算（目標、週のまとめ、総負荷量、推定1RM など）だけを受け持ちます。サーバーはデータ（JSON）だけを返し、表やグラフはチャットの側が作ります。

食事のツールの設計は [meals-design.md](meals-design.md)、ログインからツールの呼び出しまでの流れは [シーケンス図](sequence.md) にあります。

## つなぎ方

`cdk deploy` の出力 `MealsMcpServerUrl`（末尾が `/mcp`）を登録します（デプロイの手順は [cd.md](cd.md#初めてのデプロイ)）。

- Claude：「設定 → コネクタ → カスタムコネクタを追加」に URL を入れます。OAuth クライアントは「Claude の公開アイデンティティを使用」のままにします
- ChatGPT：開発者モードでアプリを作成し、URL を入れて認証方式に OAuth を選びます

登録すると認可API のログイン画面が開くので、本人のユーザーで「パスキーでサインイン」を選んでログインし、同意画面で「許可する」を押します（OAuth 2.1、PKCE）。
アクセストークンはこの MCP サーバー（食事と筋トレ）だけに使え、5分で切れます（切れたらリフレッシュトークンで更新します）。

### 同意のやり直し

**筋トレのツールを足す前につないだコネクタは、同意し直すまで筋トレのツールが使えません**（「許可がありません」と返ります。食事のツールはそのまま使えます）。
アクセストークンとリフレッシュトークンは、同意したときの scope（`meals:read`・`meals:write`）のままだからです。
コネクタの連携を解除して（または `logout` を頼んで）つなぎ直し、同意画面に筋トレの読み書きが出ていることを確かめて「許可する」を押します。URL は変わらないので、コネクタを登録し直す必要はありません。

## 食事の頼み方

| 頼み方 | 起きること |
|---|---|
| 写真を貼って「昼ごはん」 | AI が料理と量を推定して表で見せ、了承を得てから記録する |
| 「朝はいつもの」「昨日の夜と同じ」 | 保存した組み合わせや前の食事を、確認なしで記録する |
| 「今日あと何を食べればいい？」 | 今日の合計と、目標までの残り（kcal・PFC）を返す |
| 「今週の食事をふり返って」「10月の食事をふり返って」 | 日ごとの kcal の推移と、PFC の割合を、表やグラフで見せる（週は月曜〜日曜の `weekly_review`、月や前の週は期間で `meal_summary`） |
| 「目標を決めたい」 | 方針（増量・減量・維持）だけでも決められる。体重や身長を答えると、kcal と PFC の目標を計算する |
| 「体重 70kg」「目標まであとどれくらい？」 | 体重を記録し、最近のペースから目標体重までの週数を出す |
| 「さっきのご飯、量を半分に」 | 記録を直す（消すこともできる） |

写真は保存しません。保存するのは、AI が写真から読み取った説明文と栄養の推定値だけです。
その日に筋トレの記録があれば、食事の目標は自動で「筋トレの日」の目標になります（「今日は休みの日の目標にして」と言えば、そちらを優先します）。

## 筋トレの頼み方

| 頼み方 | 起きること（ツール） |
|---|---|
| 「今日のベンチプレス 80kg 8回を3セット、懸垂10回」 | その日に記録し、総負荷量と自己ベストを超えたかを返す（`record_workout`） |
| 「今日のトレーニングを見せて」「11月の記録」 | 1日の記録（`get_workout`）、期間の一覧（`list_workouts`） |
| 「2セット目は6回だった」「スクワットは消して」「昨日の分だった」 | 直す・消す・日を移す（`update_workout`、`delete_workout`） |
| 「ベンチプレスの伸びは？」 | 日ごとの総負荷量と推定1RM の推移、自己ベスト（`exercise_history`） |
| 「今週の筋トレをふり返って」 | 週の回数、総負荷量、部位ごとの割合（偏り）、前回からの日数、先週との比べ（`weekly_training_review`。週は月曜〜日曜） |
| 「ハンドスタンドプッシュアップを肩に足して。体重の9割」「膝つき腕立ての割合を40%に」 | 回数だけの種目の、体重に対する割合を決める・変える（`add_exercise`、`update_exercise` の `bodyweight_ratio`）。過去の記録の総負荷量も新しい割合で出る |
| 「種目の一覧」「ケトルベルスイングを脚に足して」 | 部位と種目（`list_exercises`、`add_exercise`） |
| 「ベンチプレスをバーベルベンチプレスに変えて」「懸垂はもう使わないので隠して」 | 種目の名前・部位を変える、隠す・表示に戻す（`update_exercise`）。過去の記録は新しい名前で出る。種目は消さず、使わなくなったら隠す |
| 「体脂肪率 15%」「体組成の推移」 | 体組成の記録と推移（`record_body`、`body_progress`。期間は `days`（今日まで）か `start`・`end`） |
| 「最近よく眠れてる？」「今週の睡眠」 | 起きた日ごとの睡眠の時間と寝た・起きた時刻、期間の平均（`sleep_summary`。今日までの7〜90日か、`start`・`end` で90日まで） |
| 「安静時心拍の推移は？」「疲れがたまってる？」 | 日ごとの安静時・平均・最低・最高の心拍と、安静時心拍の平均（`heart_rate_summary`。今日までの7〜90日か、`start`・`end` で90日まで） |
| 「今週どれくらい歩いた？」「歩数の推移」 | 日ごとの歩数の合計と、記録がある日の平均（`step_summary`。今日までの7〜90日か、`start`・`end` で90日まで） |

- 回数だけの自重の種目（懸垂・腕立て伏せなど）も総負荷量に入ります：その日の体重 × 種目の割合 × 回数。体重はその日の体組成の記録（Health Connect の取り込みを含む）で、なければ30日以内のいちばん近い前の日の体重。それもなければ入れず、応答の `note` で知らせます。推定1RM と自己ベストは、自重の種目では出しません
- 計算（総負荷量、推定1RM、自己ベスト、体脂肪量など）はアプリと同じ式で、`testdata/training/*.json` で両方が同じ結果になることを確かめています
- 種目は名前で指します。「ベンチ」のように略すと、サーバーは推測で選ばず、候補（「ベンチプレス」など）を返します
- 睡眠・心拍・歩数は、アプリが Health Connect（ウォッチなど）から取り込んで同期したものを読むだけです（MCP からは書けない）。心拍と歩数は1日のまとめ（歩数は1日の合計）だけで、1回ごと・1件ごとの値はサーバーにありません。病気の診断はしません

## ケガの記録の頼み方

| 頼み方 | 起きること（ツール） |
|---|---|
| 「ベンチの3セット目で右肩の前を痛めた。肘が開いてたと思う。次は肘を45度にたたむ」 | ケガを記録する（`record_injury`。直している途中として）。部位はコード（`shoulder_front` など）、左右は `side` |
| 「ケガの記録を見せて」「まだ直していないケガは？」 | 一覧と振り返り（`list_injuries`。`status` で絞れる） |
| 「肘をたたんだら痛くなかった」「まだ少し痛む」 | その後の振り返りを足す（`add_injury_review`：直せた・まだ・痛んだ） |
| 「肩はもう直った」 | 直せたにする（`mark_injury_fixed`。直せた日を入れる） |
| 「直し方を変える」「やっぱりまだ直っていない」 | 書き直す、直している途中に戻す（`update_injury`） |
| 「さっきのケガの記録は消して」 | 消す（`delete_injury`。振り返りも一緒に消え、アプリからも消える） |

- 原因（`cause`）と直し方（`fix`）は、利用者の言葉をそのまま残します。言っていなければ空のままにし、AI が推測で埋めないようにツールの説明で頼んでいます（あとで `update_injury` で足せる）
- 痛みの強さ・体調・診断は持ちません。AI は聞かず、診断や治療の助言もしません
- 部位は筋肉17・関節8のコードです（`services/training/training/domain/injury.py` の `SITES`）。左右のある部位は `side`（`left`・`right`）で分け、左右のない部位（`abs`・`neck`・`waist`）は左右を持ちません。脊柱起立筋は背中上部（`upper_back`）と腰（`lower_back`）に分け、どちらも左右があります（`lower_back` は 2026-11 まで左右なしで、そのころの記録は左右なしのまま読めます）。左右を言っていないときは左右なしで記録します
- 種目は、筋トレの記録と同じく名前の完全一致で選びます（見つからなければ候補を返す）
- 振り返りで「直せた」にしても、ケガの状態は変わりません（直せたにするのは `mark_injury_fixed`）
- 1人200件まで、振り返りはケガ1件に100件まで。`list_injuries` は一度に50件まで、振り返りはケガ1件に新しい20件まで（全部の数は `review_count`）
- 記録したら、次にその種目を記録するときにアプリに直すことが出る、と AI が伝えます（アプリの画面は別の PR）

## レポートの頼み方

| 頼み方 | 起きること（ツール） |
|---|---|
| 「今週のまとめを作って」「10月をふり返ってレポートにして」 | AI が期間の材料（`period_overview`。週は月曜〜日曜、月は月の初日〜最後の日）を1回で読んで書き、保存する（`save_report`）。くわしく見たいときは記録のツール（`weekly_training_review`、`body_progress`、`sleep_summary` など）も読む。アプリのホームの「最新のレポート」と一覧に出る |
| 「今日のまとめを作って」「3日前のまとめを作って」 | AI がその日の材料（`period_overview` の `start`・`end` をその日に）を読み、短めのまとめ（日のまとめ。`kind` は `daily`、期間はその日だけ）を保存する |
| 「前のまとめと比べて」 | 保存したレポートを読む（`list_reports`、`get_report`） |
| 「さっきのレポートは消して」 | 消す（`delete_report`。アプリからも消える） |

- 種類（`kind`）は、日のまとめ（`daily`）・週のまとめ（`weekly`）・月のまとめ（`monthly`）の3つで、`save_report` では必須です。その他（`other`）はもう保存できません（前に保存した `other` のレポートは消さず、一覧・取得ではそのまま読めます）。日のまとめは期間の初日と最後の日（`period_start`・`period_end`）が同じ日でないと断ります。種類を知らない前の版のアプリは、その他として見せます
- レポートは、全体の調子（`overall_tone`：良い調子・いつもどおり・気をつけたい）、ひと言の要約（`headline`）、分野ごとの要点と数字（`highlights`。6件まで）、次の一歩（`next_steps`。3件まで）、つながり（`links`。分野をまたぐ気づき。3件まで）、目標の見直し（`review`）、くわしい本文（`body`。Markdown、20,000字まで）を持ちます。アプリは調子を色・アイコン・ラベルで、数字を前の期間からの変化と一緒に見せます
- 種類ごとに書くこと（`save_report` の説明で AI に頼む）：日＝その日の目標に対する一言と、明日の一歩を1つ。週＝今週の目標の達成、つながり、来週の焦点に相当する一歩を3つまで（先に、前の週のまとめの次の一歩の結果 `previous_next_steps` を振り返ってから書く）。ケガは `period_overview` の `injuries`（`reviewed`・`fixing`）を見て、直し方を守れたかを振り返りに書く（`highlights` の分野には入れない）。月＝体の変化（体重の推移と目標までのペース）、BIG3、つながり、目標の見直しの提案、今月の課題に相当する一歩を3つまで。達成の数字そのもの（今日の達成、今週の目標、体の変化のグラフ）はアプリが記録から計算して見せるので、レポートには持たせません
- つながり（`links`）の1件は `from_area`・`to_area`（`training`・`meals`・`body`・`sleep`。違う分野）と `text`（120字まで）、任意で `basis`（「2日」「3週」のような根拠の短い言葉。20字まで）。目標の見直し（`review`）は `text`（200字まで）と、任意で `target`（いまは `meals_goal` だけ。アプリが食事の目標を開くボタンを出す）。どちらも省けて、ない前の形のレポートも読めます
- 数字は記録のツールが返した値だけを使うよう、ツールの説明で AI に頼んでいます。サーバーは値の種類・件数・長さを確かめ、1人200件までにしています。同じ種類・期間のレポートがすでにあるときは、新しい方で置き換えます（重複はできません。次の一歩のチェックは、文面が同じ一歩にだけ引き継ぎます）。期間のないレポートは置き換えの対象にしません
- 本文はモデルが書いた文なので、アプリは文字として表示するだけです（見出し・箇条書き・太字・段落だけを整え、HTML やリンクは開きません）
- アプリからは読むのと消すのだけで、書き換えはできません。筋トレの scope（`training:read`・`training:write`）を使うので、筋トレのツールを足す前につないだコネクタは、同意し直すまで使えません

食事を記録するとき、AI が kcal と PFC を推定したら、その根拠（例「ごはんは茶碗1杯 150g として」）も `record_meal` の `basis` に残し、アプリの食事の画面に出します。

| レポート | `delete_report` | レポートを消す（アプリからも消える） |
| その他 | `logout` | ログアウトする（別のアカウントで入り直すとき、連携をやめるとき） |

食事のツールは `services/meals/meals/presentation/mcp_server.py`、筋トレとケガのツールは `services/training/training/presentation/mcp_tools.py`、レポートのツールは `services/reports/reports/presentation/mcp_tools.py`、`logout` は `services/mcp/connector/tools.py`、`period_overview` は `services/mcp/connector/period_overview.py`（筋トレ・食事・設定をまたぐので、組み立ての場所）にあります。

### 期間の材料（`period_overview`）

レポートを書くチャットが何度もツールを呼ばずに済むよう、期間（`start`・`end`。両端を含む、31日まで。省くと両方とも今日）の材料を1回で返します。筋トレの scope（`training:read`）が要ります。

| 項目 | 中身 |
|---|---|
| `from`・`to`・`days` | 期間と日数 |
| `training` | `sessions`（筋トレをした日数）、`total_volume`、`days`（筋トレをした日ごとの `date`・`volume`・`sets`）、`exercises`（種目ごとの期間の最高の推定1RM：`exercise`・`body_part`・`max_estimated_1rm`・`weight_kg`・`reps`・`date`。大きい順に20件まで。自重の種目は出ない）、`exercises_omitted`（20件を超えた数）、体重がなくて総負荷量に入らなかった自重のセットがあれば `note` |
| `meals` | `weekly_review` と同じ形から `from`・`to`・`goal` を除いたもの：`recorded_days`・`total_days`・`average_of_recorded_days`・`average_target`・`gap`・`days`（日ごとの `date`・`day_type`・`recorded`・`kcal`・`protein_g`・`fat_g`・`carbs_g`・`target_kcal`） |
| `body` | `days_recorded`、`average_weight_kg`、`average_body_fat_pct`、`weekly_weight_change_kg`（`end` までの28日）、`days`（体重か体脂肪率がある日の `date`・`weight_kg`・`body_fat_pct`） |
| `sleep` | `nights_recorded`、`average_asleep_min`、`nights`（起きた日ごとの `date`・`asleep_min`・`bedtime`・`wake_time`。日本時間） |
| `heart_rate` | `days_recorded`、`average_resting_bpm`、`days`（安静時心拍がある日の `date`・`resting_bpm`） |
| `steps` | `days_recorded`、`average_steps`（記録がある日の平均。整数）、`days`（記録がある日の `date`・`steps`。1日の合計） |
| `goals` | `meals`（食事の目標。`today_status` の `goal` と同じ形。なければ null）、`goal_weight_kg`（アプリの設定の目標体重。なければ食事の目標の目標体重）、`weekly`（今週の目標：`training_days`・`meal_days`・`sleep_days`。週の日数で 0〜7、0 は「切」、未設定は null） |
| `injuries` | ケガの記録（本人の言葉のまま。原因は推測しない）：`occurred`（期間に痛めたもの）、`reviewed`（期間に振り返りを書いたもの。`reviews` はその期間の振り返りだけで、`date`・`result`・`note`・`exercise`、新しい順に5件まで。`review_count` は期間の振り返りの数）、`fixing`（`to` の時点で直している途中のもの。`to` より後に直せたにしたものも含む）。各ケガは `injury_id`・`occurred_on`・`site_name`（左右つき）・`exercise`・`phase`・`symptom`・`cause`・`fix`・`status`・`fixed_on`。それぞれ新しい順に10件まで、全部の数は `occurred_total`・`reviewed_total`・`fixing_total`。ケガの読み出しは `list_injuries` と同じ `TrainingQueries.injuries`。レポートの `highlights` の分野には入れない |
| `previous_next_steps` | 前の週のまとめ（`start` の7日前〜前の日に終わる `weekly`。いくつかあればいちばん新しいもの）の次の一歩：`report_id`・`title`・`period_start`・`period_end`・`steps`（`text`・`done`。`done` は利用者がアプリでチェックしたか）・`done_count`・`note`。次の一歩のあるまとめがなければ null。食事の `weekly_review` も同じものを返す |
| `last_app_sync_at` | ほかのツールと同じ |

今週の目標は、アプリの設定（同期の `setting`）から読みます。ID は `weekly_goal_training_days`・`weekly_goal_meal_days`・`weekly_goal_sleep_days`（ほかの設定と同じ snake_case。なければアプリの設定の名前 `weeklyGoalTrainingDays` などを読む）。値は整数の文字列で、0〜7 の整数でなければ null にします。

## アプリと MCP で同じデータを使う

アプリから送られた記録も MCP から書いた記録も、サーバーの同じ「変更の記録」を通り、同じ「今の状態」になります。同じ人かどうかは Cognito の `sub` で決まります。
アプリで記録した筋トレ・体組成（Health Connect から取り込んだ睡眠・心拍・歩数も）は、アプリが同期したあとに MCP から見えます（アプリはログインしているとき、起動・前面に戻ったとき・記録の保存のあとに同期する）。同期の前の記録は見えないので、MCP の筋トレのツールは、応答に `last_app_sync_at`（アプリから最後に同期で受け付けた時刻）を付けています。

同じ記録を両方で変えたときは、項目ごとに次の順で強い方が残ります（[同期の設計](sync-design.md#今の状態への当てはめ)）。

1. 手入力（アプリ・MCP）は、Health Connect などの取り込みより強い
2. 変えた時刻が新しい方（端末の時計が進んでいても、受け付けた時刻で切る）
3. 時刻が同じなら、あとに受け付けた方

違う項目を変えたときは両方が残ります。削除と変更がぶつかったときは削除が勝ちます。

体組成の1日の値（`body_progress`、食事の `goal_progress` の体重）は、項目ごとに、その日の手入力（アプリ・`record_body`・`record_weight`）のいちばん新しい記録を使い、手入力がない項目だけ Health Connect の取り込み（体重計など）を使います。アプリの体組成の画面と同じです（`testdata/training/body.json`）。
